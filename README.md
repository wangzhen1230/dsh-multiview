# dsh-multiview · 标签页（MultiView）

一个 DeepSeek Harness 插件：在一个桌面窗口里，用浏览器式标签栏同时加载多个**相互隔离**的客户端，并让主页的**官方插件配置**在每个标签页里同样生效。

> 一个桌面端 = 主页 + 任意多个标签页。每个标签页是独立的进程、独立的数据目录：它装的插件不影响主页，主页的插件也不会自动跑进它——除非你明确复制。

兼容桌面端：`>= 0.2.0-rc.2`（在 `0.2.0-rc.2` 上开发与实测；更晚版本的破坏性变更均不涉及本插件依赖的接口，但那些版本**未实测**，升级后建议回归一遍「新建 → 独立模式 → 固定端口」）。

## 安装

**从 GitHub 安装（推荐）**：设置 → 插件 → 添加插件，粘贴

```
github:wangzhen1230/dsh-multiview
```

或直接填仓库地址 `https://github.com/wangzhen1230/dsh-multiview`。装好后点「启用」，重启应用生效。

**从本地目录安装（开发用）**：同一入口粘贴插件目录的**绝对路径**（如 `C:\Users\你\Desktop\dsh-multiview`）。本地路径会建 junction，改动源码重启即生效。

前置条件：

- 桌面端 `>= 0.2.0-rc.2`（插件需要该版本提供的 profile 模板与启动器参数）；
- 插件**无需**发布到 npm，也**无需**任何签名或白名单；
- 本插件没有安装构建脚本，不会触发 pnpm 的构建授权拦截。

> 安装校验：装好后插件页应显示 **分界面 MultiView**（中文界面）或 **MultiView · Sub-interfaces**（英文界面），而不是包名 `dsh-multiview`。若只显示包名，说明 `locale/*.json` 未被读取。

## 新建标签页：工作区、复制选项与插件运行方式

点「＋ 新建标签页」会先让你选一个工作区（列表来自主页），并可选择：

| 选项 | 行为 |
| --- | --- |
| ☐ **复制主页插件** | 把主页已安装的第三方插件声明到新标签页，并**启用**主页当前已启用的那些 |
| ☐ **复制所选工作区的会话** | 把所选工作区在主页的会话复制进新标签页，并把会话归属写进它自己的工作区记录（第一次打开就能看到） |
| ○ **依托主页**（默认） | 标签页内嵌在主页窗口里；第三方插件的运行数据（登录态、播放状态等）与主页**共用**。适合官方插件与轻量使用 |
| ○ **插件独立运行（独立窗口）** | 复制并启用主页的插件，然后**在独立浏览器窗口按标签页自己的地址打开**——插件在自己进程里运行，登录态、播放状态**完全独立**，两个标签页可以登两个不同账号 |

点「取消」则什么都不创建。

不勾选时的初始状态：

| 项 | 初始状态 |
| --- | --- |
| **第三方插件** | 不加载：连声明都不写 |
| **官方插件** | 来自官方模板，照常加载；其配置跟随主页（见下） |
| **工作区** | 只有你刚选的那一个 |
| **会话** | 空的 |
| **模型配置** | 跟随主页（凭据共享，模型选择与目录镜像） |

**为什么需要「独立运行」**：「前后端协作」型插件（如音乐面板、书房类）的界面半边用写死的根路径向自己的后端要数据。在内嵌标签页里，这些请求会落到主页地址——那里没有该标签页插件的"后厨"，于是报错（如「响应解析失败（HTTP 404）」）。独立模式把窗口开到标签页**自己的地址**（按 id 确定性分配的稳定端口，被占用自动顺延），请求落在自己进程里，插件完整运行。

## 日常使用

### 窗口顶部

标题栏有两个控件：**标签 N**（展开标签选项菜单）与**标签栏开关**（收起/展开标签栏，状态持久化）。

**标签选项菜单**：

- ＋ 新建标签页
- 关闭全部标签页（红色，唯一批量关闭项）
- 每个标签页一行管理区：重新打开 / 复制打开 / 浏览器打开 / 清空会话 / 重置 / 关闭
- 「从主页复制」区：插件 / 工作区 / 会话

### 标签栏

- 最左「主页」标签没有任何控件：主页永远固定在标签栏，不可关闭；
- 标签页标签保留 ☆/⭐（收藏到常用列表）、⧉（独立浏览器窗口）、✕（关闭）；
- 双击重命名（仅标签页）；拖动排序；未运行时显示「启动标签页」按钮；
- 长按（约 320 ms）标签页标签、侧栏文件路径、侧栏设置入口，可拖出为独立窗口。

## 关闭 ≠ 删除：三种操作三种后果

| 操作 | 后果 |
| --- | --- |
| **✕ 关闭标签** | 进程停止、标签消失；**数据目录原样留在本地**（插件、工作区、会话、配置都在），随时可恢复 |
| **清空会话** | 只清**当前工作区**的会话，然后回到该工作区（其他工作区、插件、配置不动） |
| **重置** | **整个数据目录删除**，回到出厂状态——这是唯一安全的删档方式 |

## 标签页记住自己的工作区

新建时选的工作区、以及之后在里面干活的工作区都会被记住：

- **重新打开** → 回到上次工作的工作区（不再跳到侧栏默认的第一个）；
- **复制打开** → **完整克隆**：插件、会话、工作区列表、运行方式全部复制，副本从源当前的工作区开始；之后两边各自独立；
- **清空会话** → 只归档当前工作区的会话，回到当前工作区。

## 常用收藏与已关闭的标签页（设置页）

设置 → **标签页设置** 分三个区：

| 区块 | 内容 | 操作 |
| --- | --- | --- |
| **常用收藏** | 你收藏的标签页（运行中或已关闭都显示，标注运行方式 ⌂ 依托主页 / ⬒ 独立运行） | 打开 / 移除 |
| **已关闭的标签页** | ✕ 关闭但未重置的（数据仍在本地） | 打开 / 收藏 / 重置 |
| **已打开的标签页** | 正在运行的 | 收藏 / 重置 |

收藏入口有两处：标签上的 ☆/⭐，或设置页的「收藏」按钮——**两边是同一个列表**。

收藏清单**全局共享**：它持久化在 `$DSH_HOME/multiview/favorites.json`（Host 端），主页窗口和每个独立窗口读写的是同一份——在任何一处收藏，另一处立刻可见；重启应用后清单仍在。旧版本存放在 localStorage 里的收藏不会迁移（首次使用共享清单时为空，重新收藏一次即可）。

## 官方插件配置跟随主页（默认开启）

每个标签页的数据目录由官方模板初始化，官方插件本来就加载。主页补丁层里配置在**官方插件**上的行（`@deepseek-ai/*`）会在每次启动时镜像进该标签页的生成 overlay，所以主页改了官方插件设置 → 下次该标签页启动即生效。一行只有在**该标签页自己的补丁层也声明了同一行 id** 时才镜像；**第三方**插件的配置行永远不会被这条路径带进来。

不想让官方配置跟随：把 multiview 行的 `config.mirrorOfficialRows` 设为 `false`。

## 工作区与会话隔离（默认开启）

每个标签页有自己的工作区列表和自己的会话。主页里增删改工作区或会话不影响任何标签页；标签页里新建的会话也不会出现在主页。实现是把该标签页的两个数据根指向它自己数据目录里的目录。仍然**共享**的东西（有意保留）：模型凭据、附件目录、以及工作区指向的磁盘目录本身——隔离的是「注册表与归属」，不是你的文件。

## 从主页复制（标签选项菜单）

| 按钮 | 复制什么 | 说明 |
| --- | --- | --- |
| **插件** | 主页已安装的第三方插件，并**启用主页当前已启用的那些** | 复制后自动重启该标签页使插件加载；之后互不影响 |
| **工作区** | 主页的工作区列表 | **替换**该标签页的列表（不是合并）；会话不跟着复制 |
| **会话** | 某一个工作区的会话 | 会先问哪个工作区；已存在的会话不会被覆盖 |

## 重置 / 删除（**请务必走这个入口**）

重置会**停止它、关闭它的浏览器窗口、删除整个数据目录**（装过的插件一起删除）。它只能通过设置页的「重置」按钮（页面内确认）或 `POST /mv/api/remove { "id": "<id>" }` 完成。

> ⚠️ **不要手动删数据目录**。手动删只会清掉 `node_modules` 里的实体，却留下**两处悬空引用**：该标签页 `package.json` 的 `dependencies` 条目、以及它的 `dsh.profile.bundles` 列表。profile 启动时会去解析一个已不存在的依赖。插件的「重置」会**同时**清掉依赖声明、bundles 条目和目录本体。
>
> 补充（2026-10 实测，Node 24）：标签页 `node_modules` 里的第三方插件是**链接**到主页包副本上的。早期 Node 的 `fs.rmSync(dir, { recursive: true })` 会顺着链接走进目标、把主页安装的插件一起删空，因此旧版文档有此警告；**在 Node 24 上实测 `fs.rmSync`、`Remove-Item -Recurse`、`unlinkSync` 三种方式均只删除链接本身，不穿透目标**（源码与 `.git` 均存活）。插件的「重置」仍会先逐个解除链接再删目录，保持与旧 Node 的兼容。

## 配置

在 profile 的 `cordis.patch.yml` 里改 multiview 行的 `config`（每个字段都可省略）：

```yaml
- id: multiview
  name: 'dsh-multiview'
  config:
    autoStart: true            # 首次使用时自动启动子进程
    maxViews: 8                # 同时运行的标签页上限
    startTimeoutMs: 120000     # 子进程报告认证 URL 的超时
    mountAuth: required        # /mv/** 鉴权；off 仅为逃生口
    browserCommand: ''         # 浏览器窗口用的可执行文件；空 = 自动探测
    windowSessionMs: 43200000  # 浏览器窗口会话 cookie 有效期（12 小时）
    workspaceWindows: false    # 长按工作区开独立窗口（默认关闭，搁置中）
    profilePrefix: 'dsh-multiview-'
    profileTemplate: 'web'     # 新标签页初始化所用的内置模板
    isolateWorkspaces: true    # 每个标签页独立的工作区与会话
    initialPlugins: 'official' # 新建只加载官方插件；'offered' = 声明第三方但不启用
    mirrorOfficialRows: true   # 主页官方插件的配置行镜像进每个标签页
    dataDirName: 'multiview-data'
    sharedRowIds:              # 从主页镜像到每个标签页的模型相关行
      - agent-default-model
      - llm-pi-ai
      - llm-deepseek
      - llm-deepseek-account
      - subagent-model-selection-settings
      - ui-model-selection
```

环境变量 `DSH_MULTIVIEW_RUNTIME_DIR` 可显式指定运行时目录；`DSH_MULTIVIEW_BROWSER` 与 `browserCommand` 等价。

## 工作原理

```
主页 (main host)
 ├─ /mv/api/*            控制接口：list / open / start / stop / close / mint-id / closed-profiles / …
 ├─ /mv/file             文件查看器（一次性 ticket 授权）
 ├─ /mv/<id>/            反向代理到该标签页的子进程（HTTP；内嵌模式）
 ├─ /mv/<id>/api/remote.mux  该标签页的 Remote 流 WebSocket（精确路径）
 └─ 子进程  →  $DSH_HOME/profiles/dsh-multiview-<id>/  （自己的端口、自己的插件）

独立运行模式：浏览器窗口直接打开子进程自己的地址（稳定端口 + 它自己的凭证），
不经 /mv 反代——这是前后端型插件能完整运行的关键。
```

要点（都实测过）：

1. **子进程不能用 `.cmd` 直接 spawn**（Windows `EINVAL`）：运行时可执行文件 + `ELECTRON_RUN_AS_NODE=1` + 桌面宿主 CLI 入口，顺带获得 asar 感知的模块解析。
2. **内嵌文档必须代理到主页同源**：桌面 shell 对非本应用 origin 的 WebSocket 改写会取消请求，且 preload 不在 iframe 里跑；子文档以普通 Web 客户端启动并注入传输地址。
3. **存储命名空间**：iframe 与主页面同源，代理为每个子文档加前缀隔离的 storage 包装。
4. **镜像配置必须用 `--patch` 传**：profile 只自动加载自己的补丁层；`--patch` 是启动器参数，须放在应用参数之前。
5. **稳定端口**：按 id 哈希到 21900–22700 区间（确定性），被占用自动顺延（最多探测 32 个），区间耗尽回退系统分配。若其他程序占用了分配到的端口，该标签页地址会变化（`--port 0` 兜底）。
6. **插件模块不能有 `export default`**：加载器用 `exports.default ?? exports` 解析。
7. **长按识别照真实 DOM 写**：按 `data-files-path` → `data-path` → `data-file-path` → `title` 顺序、沿父链最多 6 层查找。
8. **镜像模型配置前确认子进程能服务该 provider**，否则选择行会让新建会话失败。
9. **「已安装」（dependencies）和「已启用」（dsh.profile.bundles）是两件事**。
10. **组件内声明的子组件每次渲染重挂载**：按在按钮上的 press 不能进长按处理。
11. **代理转发 POST**：流式 body 下连接级头由上游决定，`set-cookie` 等需剔除。
12. **浮层用官方菜单材质**：`--dsw-specific-menu` + `--dsw-menu-backdrop-filter`，随外观设置变化。

## 诚实的限制

- 独立窗口是操作系统浏览器窗口，不是新的应用窗口（宿主硬限制）；关闭/停止标签页会一并关掉它的窗口。
- **窗口大小会被记住**（每个标签页独立，存于 `$DSH_HOME/multiview/windows/<id>/window.json`）：调整好窗口大小后，下次按同样大小打开。Windows 上通过后台探测读取真实窗口矩形（打开约 2.5 秒后采样一次）；其他平台暂按 Chromium 默认尺寸打开。
- 改完代码要重启应用（HMR 不监听源码 + 模块缓存）。
- 每个标签页是一个完整进程：启动要几秒、占一份内存；`maxViews` 默认 8。
- 标签页的插件要在它自己的数据目录里安装/启用；用「从主页复制 → 插件」或新建勾选带过来。
- 收藏清单**全局共享**：持久化在 `$DSH_HOME/multiview/favorites.json`，主页与每个独立窗口读写同一份。
- 稳定端口段可能被其他程序占用（自动顺延，地址随之变化）。
- 兼容性目标为 `0.2.x`；官方破坏性变更（如移除导出、插槽改名）发布时需要跟进适配。
- 本插件不 import 任何 `@deepseek-ai/*` 包（只用 node 内置模块），但**依赖一批非公开接口**：`insert` 补丁方言、`--patch` / `--from-default-profile` / `--dump-config` 启动参数、`$DSH_HOME/profiles/<name>` 目录布局、`/mv/` 反代与 `api/remote.mux` 精确 WS 路径、`__DSH_TRANSPORT__` 全局注入、`shell.overlay` 等插槽名。官方若改动这些，插件会失效——这是本插件最脆的地方。
- 子界面里第三方插件的链接是 **best-effort**：主 profile 的插件目录若解析不到真实路径，只能声明依赖（插件页可见）而无法真正加载，需在该子界面的插件页里自行安装一次。

## 开发

```powershell
# 跑验证脚本（对真实模块跑，不联网、不 spawn 真实子进程）
node tests\verify.mjs .
```

插件是 **no-build** 的：`lib/*.js` 就是源文件本体，改完重启应用生效（Host 半边）或刷新页面（Client 半边）。提交时**不要**把 `lib/` 加进忽略。

### 本地链接开发（改代码即时生效）

要用「改源码 → 重启即生效」，profile 里必须记成 **链接**而不是快照。在插件页「添加插件」粘贴**源码目录的绝对路径**即可——pnpm 会自动写成 `link:` 并建 junction（无需手写 `link:`）：

```
C:\path\to\dsh-multiview
```

怎么判断当前是哪种模式：

```powershell
# junction = 链接开发；real dir = github 快照（改源码无效）
(Get-Item "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-multiview" -Force).LinkType
```

| profile 清单里的 specifier | node_modules 实体 | 改源码后 |
| --- | --- | --- |
| `link:C:/…/dsh-multiview` | Junction | 重启应用即生效 |
| `github:owner/dsh-multiview` | 真实目录（codeload 快照，**冻结**） | **无效**，跑的是那份快照 |

> ⚠️ **从链接切到 `github:` 后，改源码就不再生效**，而且插件给子界面复制插件时会把这个"冻结"一并传染给每个子界面。要恢复开发：在插件页卸载后，重新粘贴**绝对路径**安装即可。

`github:` 安装是 codeload 下载的**打包快照**，不会跟随你的工作区；`link:` 才指向源码目录。

### 不要用命令行装

`dsh plugin --profile desktop add` 要求应用**完全退出**才能运行，否则 profile 的 `package.json.lock` 会报 `EPERM`。**应用运行中一律走插件页 UI。**

### 发版

```powershell
# 1) 先升 version（package.json），否则同一版本号会对应多个不同内容的 commit
# 2) 跑验证
node tests\verify.mjs .
# 3) 提交并推送
git add -A
git commit -m "fix: ..."
git push
```

用户想锁定到确定版本（不跟 `main` HEAD 漂移），可带 commit SHA 安装：

```
github:owner/dsh-multiview#<full-commit-sha>
```

实测 lockfile 会记录成 `tar.gz/<sha>` 并正确识别版本号，内容不可变。
